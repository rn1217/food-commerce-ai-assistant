# Food Commerce AI Assistant 프로젝트 설명 자료

이 문서는 기존 포트폴리오에 내용을 옮길 때 사용할 사실과 근거를 정리한 자료입니다. 포트폴리오 HTML은 수정하지 않았습니다.

## 소개

자연어로 입력한 가격·선물·포장·당도 조건을 구조화하고, MySQL의 상품을 검색해 Gemini가 추천 이유와 FAQ 답변을 제공하는 로컬 웹 서비스입니다. Python/FastAPI 서비스 개발, 데이터 검증, SQL 조회, 외부 AI API 연동, 오류 처리와 검증을 함께 경험하기 위해 구현했습니다.

- 유형: 개인 학습·포트폴리오 프로젝트, AI 코딩 도구 활용.
- 범위: 가상 상품 30개, 가상 FAQ 10개, 로컬 실행. 배포·실제 고객 운영 제외.
- 기술: Python, FastAPI, MySQL, pandas, Gemini REST API, HTML/CSS/JavaScript.
- 기간 표기는 본인의 실제 작업 기록을 확인해 기재합니다. 본인 기여는 이해하고 수행한 설계·실행·검토 범위에 맞춰 설명하며 모든 코드를 독력으로 작성했다고 표현하지 않습니다.

## 핵심 구현과 이유

1. 자연어 조건을 엄격한 스키마로 제한하고 SQL은 Python에서 조립했습니다. 모델이 임의 SQL을 실행하지 않도록 검색 조건과 조회를 분리했습니다.
2. 상품명·가격은 DB에서 가져오고 후보 ID를 검증했습니다. 설명은 최대 3개에 생성하고 전체 검색 결과는 유지했습니다.
3. FAQ 답변에 근거 원문과 출처를 함께 보여줍니다. 근거 없음·동점·생성 실패를 구분합니다.
4. pandas로 CSV를 검증하고 중복 입력 및 기존 ID 충돌을 처리했습니다. 오류 시 일부 저장을 막기 위해 롤백합니다.
5. 요청 ID로 질문·응답·처리 시간·오류를 연결했습니다. API 장애가 서비스 전체 중단으로 이어지지 않도록 대체 응답을 제공합니다.

## 대표 문제 해결 사례

증상: 지원 가능한 복합 질문에 상품이 나오지 않았습니다. 로그에서는 선물·포장·당도는 해석됐지만 요청 동사 “추천”이 미지원 조건으로 분류됐습니다.

조치: 요청 동사와 상품 조건을 구분하는 지시 및 지원 예시를 추가했습니다. 검증을 우회하거나 미지원 조건을 무조건 삭제하지 않았습니다.

확인: Flash-Lite에서 같은 고정 질문 3개를 재실행했을 때 통과가 2/3에서 3/3으로 바뀌었습니다. 이는 개발용 고정 사례 재검증이며 일반 정확도 개선률이 아닙니다.

별도 사례: 기존 모델의 503·시간 초과는 로그로 구분하고 제한된 재시도와 모델 비교를 진행했습니다. 외부 서비스의 상세 장애 원인은 확정하지 않았습니다.

원본: [평가 보고서](evaluation/product-validation.md), [개발 기록](devlog/2026-10-06.md).

## 사용할 수 있는 수치

| 수치 | 함께 명시할 범위 |
| --- | --- |
| 상품 30개 / FAQ 10개 | 모두 가상 데이터 |
| 자동 테스트 60개 통과 | DB·LLM 모의 처리 |
| 실제 DB 검색 15개 통과 | 고정 조건·기대 ID 검사 |
| 실제 자연어 3개 통과 | 고정 질문, 단일 실행, 실제 HTTP·LLM·DB 로그 |
| HTTP 6.49 / 6.843 / 7.259초 | 각각의 요청 관측값. 평균 성능·서비스 SLA 아님 |

“환각 완전 방지”, “정확도 100%”, “매출 증가”, “토큰 90% 절감”은 측정·보장하지 않은 내용이므로 사용하지 않습니다.

## 면접에서 설명할 내용

- AI가 맡는 조건 해석·설명과 Python/MySQL이 맡는 검색의 차이.
- 실제 상품 ID만 반환하도록 검증해도 설명 문장의 사실성 검토가 필요한 이유.
- 가성비를 가격순으로 제한한 이유와 중량 데이터 부재.
- 요청 ID로 실패 단계를 찾고 동일 질문을 다시 검증하는 방법.
- 현재 데이터 규모에서 SQL·키워드 검색을 선택한 이유와 향후 평가셋 확장 계획.
