# Gemini 연결 테스트

## 목적과 파일

웹 화면과 DB를 연결하기 전에 Python에서 질문 하나를 보내고 답변을 받는지 확인한다. `scripts/check_llm.py`가 프로젝트 루트의 `.env`를 읽고 공식 Google API로 POST 요청을 보낸다. 상품 추천 웹 API에도 LLM을 연결했다. 자세한 내용은 llm-recommendation-guide.md를 참고한다.

흐름: `.env` 인증키 로딩 → 질문을 JSON 문자열로 변환 → HTTPS 요청 → JSON 응답의 텍스트 추출 → 터미널 출력.

`GEMINI_API_KEY`는 인증에 사용하며 출력하지 않는다. `LLM_MODEL`로 모델을 설정한다. 추가 패키지는 필요 없고 기존 python-dotenv와 Python 표준 라이브러리를 사용한다.

## 실행

프로젝트 폴더의 PowerShell에서 다음을 실행한다.

```powershell
.\.venv\Scripts\python.exe -B -m scripts.check_llm
```

정상 결과는 `연결 성공`, 모델 이름, 짧은 한국어 답변과 응답 시간이다. 문구와 시간은 실행마다 달라질 수 있다. 자동 재시도는 하지 않는다.

## 오류와 완료 조건

- 키 누락: 프로젝트 루트 `.env`의 GEMINI_API_KEY를 확인하고 파일 저장.
- 400/401/403: 요청 형식, 키, 권한 또는 이용 가능 여부 확인.
- 404: 설정한 모델 이름과 지원 여부 확인.
- 429: 무료 등급의 할당량 확인. 결제 연결 없이 중단하고 나중에 재시도.
- 503: 서비스 이용 불가 응답. 시간이 지난 뒤 재시도. 키가 정상이라는 의미는 아님.
- 네트워크 오류: 인터넷 연결 및 실행 환경의 네트워크 권한 확인.

이번 확인에서는 키 누락 검사를 통과했으나 실제 호출은 HTTP 503으로 끝났다. 이후 사용자 연결 테스트와 10/2 상품 추천 통합 검증에서 실제 답변 수신에 성공했다. 연결 성공과 답변 출력이 완료 조건이며, 그 뒤 상품 후보를 전달하는 단계로 진행한다.
