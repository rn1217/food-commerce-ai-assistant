# 2026-10-06 — FAQ AI 답변 연결

## 구현과 선택

기존 FAQ 검색 뒤 Gemini 답변 생성 단계를 추가했다. 근거 없음/동점이면 호출하지 않고, 검색 결과가 있어도 모델이 답변 불가로 판단하면 생성 문장을 표시하지 않는다. AI가 출력한 출처는 검색 후보 ID 목록에 있는지 검증한다. 형식 오류·중복/미등록 출처·빈 답변·API 오류는 원문 표시로 대체한다.

UI에 생성 답변과 원문 출처 링크를 추가했다. 새 패키지·DB 테이블 변경 없이 기존 LLM HTTP 호출과 요청 로그 구조를 재사용했다.

## 검증

자동 테스트 52개 통과. 외부 호출/DB 쓰기는 모의 처리했으며 생성 성공, 생략, 답변 보류, 출처 오류, API 503/429/시간 초과 및 로그 실패를 확인했다.

실제 HTTP와 MySQL/Gemini로 다음 3건을 확인했고 DB의 response JSON과 HTTP 응답이 모두 일치했다.

- 배송비는 얼마인가요?: mode=generated, 기본 배송비 3,000원/50,000원 이상 무료, 출처 faqs:2. request_id=2f572999-0548-47b2-9597-1cb034bd202b. LLM 처리 8,810ms, 입력 379/출력 65/총 토큰 1,034. 단일 요청 관측이며 평균이 아니다.
- 배송: needs_clarification, 생성 호출 생략.
- 비트코인 가격 알려줘: no_match, 생성 호출 생략.

첫 수동 검증은 PowerShell 파이프의 문자 인코딩으로 질문이 물음표로 전달됐다. UTF-8 OutputEncoding을 명시해 재검증했고 해당 3건은 정상 질문 평가에서 제외했다. 이 실패는 서비스의 한글 처리 오류가 아니며 테스트 실행 환경 문제였다.

브라우저 도구가 사용 불가여서 이번 화면 클릭·출처 이동·레이아웃 검증은 미실시했다. 브라우저 수동 확인 항목은 faq-ai-guide.md에 남겼다.

## 한계와 다음 작업

검증은 출처 ID와 응답 형식을 검사하며 생성 문장의 모든 사실을 보장하지 않는다. FAQ 검색은 키워드 기반이다. 상품 30~50개 확장, 고정 평가 질문, ERD/구조도와 포트폴리오 정리가 남았다.


## 반복 503 대응

사용자가 배송비 답변 실패를 보고했다. 최근 배송비 로그 5건에서 http_503을 확인했다. 같은 모델·API로 짧은 요청을 다시 보냈을 때 completed가 반환되어 지속적인 인증/설정 오류로 단정할 수 없었다. 서버 과부하 등 상세 원인은 확정하지 못했다.

503에만 1초 뒤 1회 재시도하고, 반복 실패는 원문을 유지하도록 보완했다. 429/인증 오류/잘못된 출력에는 재시도하지 않는다. attempts를 성공/실패 메타데이터에 기록한다. 자동 테스트 54개 통과: 첫 503 후 성공, 두 번 실패 후 중단, 429 재시도 없음 등을 검증했다.

## FAQ 모델 분리 및 최종 확인

재시도 추가 후에도 기존 gemini-3.8-flash의 실제 FAQ 요청에서 시간 초과(20,110ms, 1회)와 503(10,070ms, 2회)이 발생했다. 같은 배송비 질문을 gemini-3.5-flash-lite로 호출했을 때 3,519ms에 성공했다. 따라서 FAQ에만 LLM_FAQ_MODEL 설정을 추가하고 Flash-Lite를 선택했다. 상품 조건 해석과 추천 설명은 기존 모델을 유지한다. 모델 변경은 장애 원인을 확정하거나 영구 복구하는 조치는 아니다.

공식 가격표에서 Flash-Lite 무료 등급을 확인했다: https://ai.google.dev/gemini-api/docs/pricing (2026-10-06 확인, 할당량과 정책은 변경될 수 있음).

최종 자동 테스트 55개 통과. 새 서버의 POST /api/faq/search 실제 요청에서 배송비 답변과 출처 faqs:2가 반환됐으며 DB 로그와 응답이 일치했다. request_id=bf134f82-3455-4dfe-920d-5f43a5fe92a3, model=gemini-3.5-flash-lite, LLM 3,131ms, attempts=1, 입력 375/출력 70/총 445 토큰. 서로 다른 호출의 단일 관측이므로 평균 성능 비교로 해석하지 않는다. 브라우저 도구를 사용할 수 없어 실제 화면 클릭 검증은 수행하지 못했다.

## 상품 30개 확장과 검증

- 기존 5개 데이터의 ID와 값을 보존하고 25개를 추가했다. data/products.csv를 pandas로 검증하고 매개변수 SQL로 저장한다. 기존 ID 내용 충돌은 중단하며 트랜잭션 롤백을 적용했다.
- 실제 첫 저장 added=25/skipped=5, 두 번째 added=0/skipped=30. GET /api/products에서도 count=30 확인.
- DB 검색 15개 고정 사례 통과, 자동 테스트 60개 통과.
- 실제 자연어 3개는 기존 모델에서 503/시간 초과로 모두 실패했다. Flash-Lite 비교에서는 2개 성공, 1개는 “추천”을 미지원 조건으로 잘못 분류했다. 요청 동사 구분과 지원 예시를 프롬프트에 추가한 뒤 같은 3개가 모두 통과했다.
- 상품용 LLM_MODEL도 gemini-3.5-flash-lite로 변경했다. 서버 재시작 필요. 상품 구조나 후보 검증을 완화하지 않았다.
- [평가 결과와 수정 전후 증거](../evaluation/product-validation.md), [파일 역할과 실행 안내](../product-data-guide.md)에 상세 기록. 고정 질문에 대한 관측이며 일반 정확도 또는 평균 성능으로 주장하지 않는다.

## GitHub 업로드 전 문서 및 재설치 확인

README의 초기 규칙 검색·pandas 예정 문구를 현재 구현으로 교체하고 설치 순서를 정리했다. 시스템 구조도, SQL 기준 ERD, 프로젝트 소개 자료, 시연/캡처 안내와 제출 체크리스트를 추가했다. 별도 포트폴리오 HTML은 수정하지 않았다.

별도 Python 3.14.7 venv에 고정 의존성을 재설치한 뒤 pip check와 자동 테스트 60개를 통과했다. 설치가 완료되기 전에 테스트를 먼저 실행한 확인 과정에서는 fastapi 미설치 오류가 있었으며, 설치 종료 확인 후 다시 실행해 통과했다. 별도 환경의 실제 HTTP 검사 9개도 통과했고 정상 POST 3건은 DB 로그와 응답이 일치했다. 외부 API 호출은 이 검사에서 꺼두고 기존 같은 날의 실연동 증거를 유지했다. 실제 MySQL 검색 15개도 다시 통과했다.

.env와 .venv의 Git 제외, .env 경로의 로컬 이력 부재, 업로드 후보 파일 내 현재 비밀정보 값 부재를 확인했다. 전체 과거 비밀정보 감사는 아니다. 기존 DB를 사용했으므로 새 PC의 MySQL 설치·빈 DB 초기화 검증과는 구분한다. 연결된 브라우저가 없어 최신 화면 캡처/시각 검증은 남겨 두었다. 커밋과 푸시는 하지 않았다.
