## 설계 결정

LLM 결제와 호출은 미룬다. 생성 답변 대신 근거 원문을 최대 3개 반환하고 `retrieval_only`로 표시한다. `배송`보다 `배송비`처럼 긴 일치 표현을 우선하며, 1위 동점은 추가 질문을 안내한다. 향후 상품 전용 FAQ가 추가돼도 공통 검색에 섞이지 않도록 product_id가 NULL인 행만 조회한다.

가상 정책의 출고 기간과 배송비는 실제 판매처 정책이 아님을 응답에 표시한다. 상품별 보관·해동 시간 등 등록되지 않은 사실은 원문에서도 추측하지 않는다.

- 자동 테스트 11개 통과. 정상 요청, 공백/누락/타입/길이 오류, 근거 없음, 동점, 원문 보존, 기존 추천 회귀 포함.

## 추가 완료 — 요청 로그

- `ai_logs` 테이블과 초기화 명령 추가. 현재는 `engine=rule`로 저장.
- 추천·FAQ의 질문, 응답 JSON, 처리 시간, 상태, HTTP 코드, 요청 ID 기록.
- finally에서 요청당 한 번 저장하며, INSERT 후 commit으로 실제 반영.
- MySQL 오류 503 및 예상하지 못한 오류 500을 기록하고, 로그 저장 실패는 원래 응답을 덮어쓰지 않도록 콘솔 fallback 처리.
- 성공 응답의 request_id와 오류 응답의 X-Request-ID 헤더로 기록 추적.
- 422 입력 검증 실패와 GET 조회는 로그 범위에서 제외함을 문서화.

### 검증

- 기존 11개에 새 로그 테스트 13개를 추가해 총 24개 통과.
- 로그만 실패한 경우 200 유지, 검색과 로그가 함께 실패하면 503 유지 확인. DB 자체를 중단하지 않고 모의 예외 사용.
- 실제 HTTP 정상/미지원/FAQ/추가 질문/근거 없음 5건과 검색 오류 주입 1건을 DB에 저장하고 응답 JSON·요청 ID·상태 대조.
- 기존 상품과 FAQ 전체 행을 작업 전후 비교해 변경 없음 확인.
- 로그 테이블 초기화 두 번 실행 가능. 검증 기록 6건은 삭제하지 않고 남김.

### 측정 기준과 남은 한계

latency_ms는 입력 검증 후 검색 함수 시작부터 응답 준비까지이며 로그 저장 시간은 제외한다. 생성 시각은 UTC이다. 기록한 시간만으로 성능 개선을 주장하지 않는다. 동기 로그 저장의 추가 대기, 콘솔 기록의 비영속성, 보존 기간·개인정보 정책 미구현은 한계로 남는다.
