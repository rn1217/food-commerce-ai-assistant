# 2026-09-21 — 추천 요청 검증과 MySQL 상품 검색

## 완료

- POST 요청 모델로 질문을 받고 앞뒤 공백 제거 후 1~500자 검증.
- 가상 상품 5개와 Python 리스트 검색 함수 작성.
- 선물·개별포장·낮은 당도 표현에서 조건 추출 후 API 연결.
- 인식한 조건이 없으면 검색을 중단하고 사용 방법 안내.
- MySQL `food_commerce.products` 생성과 상품 입력, SQL 조건 검색 실습.
- `.env`, PyMySQL, DictCursor를 사용해 FastAPI와 MySQL 연결.
- `GET /api/products`와 추천 API를 실제 DB 조회로 구현.
- 파라미터 바인딩, 연결 정리, MySQL 오류의 서버 로그와 503 응답 처리 추가.
- 주요 코드에 역할과 데이터 흐름을 설명하는 주석 추가.

## 문제 → 원인 → 개선

| 문제 | 원인 | 개선 및 비교 |
| --- | --- | --- |
| 공백만 있는 질문도 통과 | 공백도 문자열 길이에 포함 | 먼저 공백 제거. 동일 입력 200 → 422 |
| 미지원 질문에 전체 상품 반환 | 추출 조건이 모두 비활성이라 전체 리스트 통과 | 조건 존재 여부를 먼저 검사. 반환 상품 수 5 → 0 |
| DB 수정이 추천에 반영되지 않는 초기 구조 | 추천이 Python의 고정 리스트 사용 | `filter_products()` 호출을 DB `search_products()`로 교체 |

SQL 실행 중 확장 프로그램 안내가 나타나 실행 위치를 다시 확인했다. 코드는 편집기에 저장하고, SQL은 MySQL Workbench의 연결된 SQL 탭에서 실행하도록 구분한 뒤 정상 실행을 확인했다. 정확한 확장 프로그램 오류 문구는 수집하지 않았다.

## 수동 확인 결과

아래 결과는 단계별 실습 후 개발자가 정상 동작을 보고한 내용을 정리한 것이다. 이번 문서 정리 중 DB를 다시 변경하거나 API를 재실행한 것은 아니다.

| 입력 또는 상태 | 결과 |
| --- | --- |
| 선물 + 개별포장 + 낮은 당도 | 상품 ID 1, 5 |
| 개별포장만 요청 | 상품 ID 1, 2, 4, 5 |
| 선물만 요청 | 상품 ID 1, 2, 3, 5 |
| 공백 질문 | 422 |
| 매운 상품 질문 | 200, 빈 목록과 지원 조건 안내 |
| DB 상품 5 비활성화 후 복합 조건 검색 | 상품 ID 1 |
| DB 상품 1, 5 비활성화 후 복합 조건 검색 | 빈 목록과 결과 없음 안내 |
| 활성 상태 복구 후 검색 | 상품 ID 1, 5 |

DB 조회 API에서 가격 변경과 응답 반영 확인 실습도 진행했다. DB 장애 시 503 처리 코드는 작성했지만 장애 재현 결과는 별도로 기록하지 않았다.

## 현재 구조와 배운 내용

`main.py`는 입력과 응답, `recommendation_service.py`는 조건 추출, `product_repository.py`는 SQL, `database.py`는 접속 정보를 담당한다.

SQL의 고정 조건 구문만 조립하고 값은 `%s`와 별도 파라미터로 전달한다. 두 API 모두 MySQL을 조회하며, 초기 리스트 검색 함수와 데이터는 비교 학습용으로 남아 있다.

## 남은 한계와 정리할 항목

- `매운 선물`에서 선물만 인식하고 부정문도 잘못 해석할 수 있다.
- LLM, FAQ, AI 요청 로그, 웹 UI는 아직 없다.
- 자동화 테스트, 응답 시간 및 토큰 측정은 아직 하지 않았다.
- 문서 작성 시 `schema.sql`에 미완성 테이블 정의가 남아 있는 것을 발견했다. 기존 DB 동작과 별개로 신규 설치 전에 정리가 필요하다.
- 설치된 PyMySQL과 python-dotenv가 `requirements.txt`에 빠져 있어 버전 목록 갱신이 필요하다.
- `main.py`의 추천 API 상단에 초기 Python 검색 흐름을 설명하는 오래된 주석이 남아 있다. 실제 함수는 DB 검색을 호출한다.
