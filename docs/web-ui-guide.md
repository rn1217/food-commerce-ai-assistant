# 웹 화면 학습 안내

## 목적과 흐름

Swagger에서 호출하던 상품·FAQ API를 일반 사용자가 입력창과 버튼으로 사용할 수 있게 한다. LLM 연동은 아직 하지 않았고, 기존 DB 검색 결과와 FAQ 원문을 표시한다.

브라우저에서 `/` 접속 → FastAPI가 HTML 반환 → CSS/JS 로딩 → 사용자가 질문 제출 → JS가 POST JSON 전송 → 기존 Python 로직이 MySQL 조회 → JSON 응답 → JS가 카드로 표시한다. 유효한 검색 요청은 기존 ai_logs 처리도 거친다.

## 파일 역할

- `app/main.py`: `/`에서 고정 HTML 파일을 반환하고 `/static`에 CSS/JS를 연결한다. 프로젝트 전체를 정적 경로로 공개하지 않는다.
- `templates/index.html`: 버튼, 입력창, 결과 영역 등 화면 구조. 별도의 템플릿 라이브러리는 쓰지 않는다.
- `static/style.css`: 색상, 간격, 카드, 작은 화면에서의 세로 배치.
- `static/app.js`: 기능 선택, 입력 검증, `fetch`, JSON 해석, 카드 생성, 오류 안내. 주요 흐름에 주석이 있다.

`fetch`는 브라우저가 서버에 HTTP 요청을 보내는 함수다. `JSON.stringify({query})`는 질문을 JSON 문자열로 만들고, `response.json()`은 서버의 JSON을 JavaScript 객체로 읽는다. `textContent`로 문자를 표시해 입력 내용을 HTML 코드로 실행하지 않는다.

## 직접 실행

프로젝트 폴더의 PowerShell에서:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

http://127.0.0.1:8000/ 에 접속한다. 예시 버튼은 질문만 채우므로 검색 버튼도 눌러야 한다.

## 예상 결과와 완료 조건

- 담백한 선물 예시: 초기 DB에서 상품 1, 5 및 가격·포장·당도 표시.
- 배송비: FAQ 원문과 `faqs:2` 출처 확인.
- 공백: 입력 오류 안내. FAQ `비트코인 가격 알려줘`: 근거 없음 안내.
- 검색 중 버튼 비활성화, 완료 후 재활성화. 좁은 화면은 입력과 결과가 세로로 배치.
- 화면의 요청 기록 확인을 열어 request_id를 확인할 수 있음.

## 오류 확인

- 접속 불가: 서버 터미널이 실행 중인지, 주소와 포트가 맞는지 확인.
- DB 오류: MySQL 실행 상태와 `.env` 설정 확인. 상세 원인은 서버 로그, 요청 추적은 request_id로 확인.
- CSS/JS 변경이 안 보임: 브라우저를 새로고침. HTML을 더블클릭해 열지 말 것.
- 통신 실패 시 입력을 유지하고 안내를 표시한다. 브라우저 대기는 30초 후 중단하지만 서버 작업 취소를 보장하지 않는다.
