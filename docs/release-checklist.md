## 검증 환경과 범위

Windows / Python 3.14.7. 기존 개발 환경과 별도로 새 venv를 만들고 고정 의존성을 설치했습니다. 프로젝트 외부 작업 폴더에서 수행해 업로드 대상에 새 venv를 추가하지 않았습니다.

이 컴퓨터의 Python Launcher에서 `py`가 설치 Python을 찾지 못해 기존 Python 실행 파일로 venv를 만들었습니다. README에는 `python` 명령과 설치 경로 사용 방법을 안내했습니다.

HTTP 검사 서버는 `LLM_ENABLED=false`로 실행해 실제 외부 API를 반복 호출하지 않았습니다. [검사 원본](evaluation/release-smoke.json)을 참고하세요. 실제 LLM 검증은 같은 날 수행한 [고정 질문 평가](evaluation/product-validation.md)와 [FAQ 개발 기록](devlog/2026-10-06.md)을 근거로 합니다.

기존 MySQL 인스턴스와 데이터를 사용했습니다. 새 PC의 MySQL 설치부터 빈 DB 초기화까지 전 과정을 재현한 것은 아닙니다. Mermaid 원문은 작성했으나 GitHub에서 렌더링된 모습은 확인하지 않았습니다.

## 사용자 확인이 남은 항목

- [ ] 서버 재시작 후 최신 화면에서 상품 추천·FAQ 답변·출처 클릭 확인.
- [ ] [캡처 안내](demo-guide.md)에 따라 실제 화면 3장 저장. 현재 연결된 브라우저가 없어 자동 캡처하지 못했습니다.
- [ ] GitHub 업로드 후 README·Mermaid 도식·상대 링크 표시 확인.

화면 이미지를 추가하기 전에도 코드 저장소를 업로드할 수 있지만, 제출용 포트폴리오에는 실행 화면을 함께 제공하는 편이 좋습니다. 위 항목을 완료한 것으로 표시하지 않았습니다.

## 커밋 직전 직접 확인할 명령

프로젝트 루트에서 실행합니다.

```powershell
git status --short
git diff --check
git check-ignore .env .venv/pyvenv.cfg
```

현재 단계에서는 커밋·푸시를 수행하지 않았습니다. 파일을 검토하고 스테이징한 뒤에는 `git diff --cached --stat`과 `git diff --cached`로 실제 커밋 내용을 확인합니다. `.env`, 가상환경, 로컬 DB 덤프가 포함되지 않아야 합니다.

이번 미커밋 작업 묶음의 커밋 메시지 예시:

```text
feat: FAQ AI 답변과 상품 데이터 검증 완성 및 제출 문서 정리
```
