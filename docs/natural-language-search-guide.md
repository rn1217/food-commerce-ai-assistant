# 자연어 조건 해석과 가격 검색

## 이번 단계의 목적

이전에는 Python이 '선물·개별포장·덜 단' 키워드만 찾고 AI는 추천 이유만 작성했다. 이제 Gemini가 질문을 제한된 검색 조건으로 해석한다. SQL과 상품 선택은 여전히 Python/MySQL이 담당한다.

## 흐름

질문 → Gemini 조건 해석 → Pydantic 검증 → MySQL 필터·정렬 → 앞 3개 후보의 AI 추천 이유 → 화면과 ai_logs.

한 요청에는 조건 해석 1회, 후보가 있으면 추천 이유 1회로 최대 2회의 LLM 호출이 있다. 검색 결과가 없을 때 생략하는 것은 두 번째 '이유 생성' 호출이다. 자동 재시도는 없다.

## 파일 역할

- `app/query_service.py`: 허용된 조건 스키마, 해석 프롬프트, 값·범위·상충 조건 검증. AI 오류 시 단순한 문장만 기존 규칙으로 처리한다.
- `app/product_repository.py`: 최소/최대 가격, 개별포장 제외, 가격순 정렬. 값은 %s 바인딩, 정렬 구문은 고정 허용 목록에서 선택한다.
- `app/main.py`: 해석 → 검색 → 이유 생성 연결. unsupported/needs_clarification이면 부분 검색을 하지 않는다.
- `static/app.js`: 가격·포장·정렬 조건을 태그로 표시. 예시 질문 및 60초 브라우저 대기 제한.
- `tests/test_query.py`: 출력 형식, 범위, 제외, 실패 시 부분 검색 방지, SQL 바인딩 검증.

## 지원 조건과 기준

| 질문 | 해석 |
| --- | --- |
| 2만원 이하 | max_price=20000 |
| 1만원 이상 3만원 이하 | min_price=10000, max_price=30000 |
| 1만5천원 미만 | max_price=14999 (원 단위 정수) |
| 개별포장은 제외 | exclude_individual=true |
| 제일 싼 상품 포함 | include_cheapest=true, 가격 낮은 순 |
| 가성비 | 판매가격 낮은 순, 중량·품질 비교가 아님을 안내 |
| 선물 가능한 상품 중 최저가 | 선물 필터를 만족하는 활성 상품 안에서 최저가 |

미지원 조건(예: 매운맛·건강 효능·배송 조건)이 감지되면 해당 조건을 안내하고 검색하지 않는다. 모든 자연어의 정확한 해석을 보장하지 않으며 적용 조건 태그를 확인해야 한다. 카테고리 필터와 대화 이력은 이번 범위가 아니다.

## 실행과 예상 결과

기존 서버를 종료한 뒤 프로젝트 폴더에서 실행한다. 새 패키지나 DB 변경은 없다.

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

http://127.0.0.1:8000/ 에서:

1. `가성비 있는 상품을 추천해줘 제일 싼 상품도 포함해서` → 초기 상품 5개가 12,000/24,000/28,000/32,000/35,000원 순서. 최저가 상품 4번이 첫 번째.
2. `2만원 이하 상품 중 개별포장은 제외해줘` → 조건 태그 2개, 현재 DB에서는 결과 0개가 정상. 묶음포장 상품이 32,000원이기 때문이다.
3. `매운 선물 추천해줘` → 매운맛 미지원 안내. 선물 조건만 적용한 결과를 추천하지 않는다.

## 오류와 설정

`.env`의 LLM_ENABLED와 LLM_QUERY_ENABLED는 기본 true다. LLM_ENABLED=false이면 모든 상품 LLM 호출을 끈다. LLM_QUERY_ENABLED=false이면 조건 해석만 끄고 제한된 기존 규칙을 사용한다. 바꾸면 서버를 재시작한다.

조건 해석 오류 시 복합 질문은 임의로 단순화하지 않고 안내한다. '선물 추천해줘' 같은 엄격한 단순 문장만 규칙으로 처리한다. 이유 생성 오류는 이미 검색된 상품을 유지한다. 로그에는 interpretation과 llm을 별도로 저장해서 실패한 단계를 구분한다. API 전체 상태 fallback일 때 error_code의 query_ 접두사는 조건 해석 오류다. 양쪽이 실패하면 두 메타데이터를 함께 확인한다.

AI 통신의 20초 제한은 개별 소켓 대기이며 전체 요청의 절대 제한이 아니다. 순차 호출로 응답이 더 느려질 수 있다. 브라우저 대기 중단도 서버 작업 취소를 보장하지 않는다.

## 검증 및 완료 조건

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
```

45개 테스트 통과. 실제 웹에서 가성비/최저가 질의의 가격순 정렬과 2만원 이하·개별포장 제외의 0개 결과를 확인했다. 실제 Gemini에 '매운 선물'을 전달했을 때 미지원 목록에 매운맛이 포함된 것을 확인했다. SQL의 가격 경계와 정렬·제외는 실제 DB 조회로도 검증했다. '미만' 자연어의 첫 실제 호출은 503으로 실패해 그 문장의 실해석 성공까지 확인한 것은 아니다.

완료 조건은 화면의 해석된 조건을 읽고 상품 가격·포장이 일치하는지 확인하는 것이다.
